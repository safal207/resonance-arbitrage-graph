# v0.16 — Predictive Opportunity Layer

## Status

Design target for the next paper-only research layer.

v0.16 adds predictive modeling **around** the existing causal verifier without granting a model authority to execute, promote, or mutate runtime policy.

The purpose is to estimate whether an observed arbitrage opportunity is likely to remain economically valid after latency, costs, liquidity, and regime effects, while preserving the repository's deterministic replay, anti-leakage, holdout, promotion, lineage, and authority guarantees.

## Causal spine

```text
captured market state
→ deterministic causal features
→ prediction request
→ model artifact + training provenance
→ prediction
→ verifier/policy context
→ paper decision
→ later observed outcome
→ realized paper PnL label
→ chronological evaluation
→ walk-forward stability
→ candidate-model evidence
```

The predictive layer is advisory. It cannot directly turn `OBSERVE` or `REJECT` into `EXECUTE_SIM`.

## Primary research question

The system should move from asking only:

> Is a visible discrepancy executable under the current deterministic policy?

Toward also asking:

> Given the exact evidence available at decision time, how likely is this opportunity to survive long enough to produce positive realized net paper PnL?

## Initial targets

v0.16 defines three prediction targets:

1. `future_net_edge_bps`
   - realized net edge at a fixed, explicitly declared future horizon;
   - includes the same modeled fee/slippage semantics used by the replay case;
   - never computed from information available after the label horizon when constructing features.

2. `opportunity_survival_ms`
   - time until the route no longer satisfies the chosen positive-edge survival condition;
   - censored/indeterminate observations must remain explicit rather than coerced into zero.

3. `positive_realized_pnl_probability`
   - probability that the route's later simulated outcome has `realized_net_pnl > 0` under the exact paper execution model bound to the case.

The third target is the initial ranking target. Accuracy is diagnostic; the economic evaluation target is realized paper PnL under untouched chronological validation.

## Feature contract

Every feature must be derivable from evidence available at or before the decision timestamp.

Initial feature groups:

### Route economics

- gross spread / expected edge bps
- fee bps
- slippage bps
- modeled gas / fixed costs where applicable
- route hop count
- start amount
- capacity ratio

### Market state

- rolling return volatility
- bid/ask spread
- quote freshness
- quote age dispersion across route legs
- rolling-window sample count and coverage ratio
- cross-rate dislocation
- derived market regime

### Route identity and structure

- semantic route ID
- venue sequence
- asset sequence
- edge direction
- same-venue versus cross-venue observation class

### Historical reliability

Only strictly prior outcomes may be used:

- prior route truth rate
- prior route survival rate
- prior prediction bias
- history confidence / sample count
- regime-segmented prior reliability

A feature builder MUST reject any history record whose observation/outcome availability timestamp is later than the current decision timestamp.

## Anti-leakage invariants

Predictive research is invalid unless all of the following hold:

```text
feature_time <= decision_time
training_outcome_available_time < evaluation_decision_time
logical_operation groups never cross split boundaries
retries remain one logical operation
validation never selects models, thresholds, hyperparameters, or fallbacks
all preprocessing state is fit on training/calibration only
```

Additional requirements:

- no random train/test split for time-series evaluation;
- no feature may contain a later final verdict or later outcome classification;
- no global normalization/statistics computed across validation/test rows;
- model selection must happen before the untouched validation segment is read for scoring;
- Optuna or equivalent search, when introduced, is calibration-only;
- failed/sparse chronological folds remain visible in evidence and are not silently dropped;
- wallet/trader observations, when later added, must obey the same event-time versus availability-time firewall.

## Baseline before deep learning

The first implementation should establish simple baselines before PyTorch/RL:

```text
constant / historical-rate baseline
→ linear/logistic baseline
→ tree baseline (LightGBM / CatBoost / XGBoost as optional research dependencies)
→ only then sequence/deep models
```

The repository core should remain dependency-light. ML libraries belong in an optional research dependency group or an external research environment; the canonical feature/prediction/evidence schemas must not require a specific ML framework.

## Prediction artifact

A prediction must not be represented as an unbound float.

A `PredictiveOpportunityReceipt` should bind at minimum:

```text
logical_operation_id
decision_timestamp
feature_schema_version
feature_vector_sha256
model_id
model_artifact_sha256
training_manifest_sha256
prediction_target
prediction_value
prediction_timestamp
policy_context_sha256
source_replay_case_sha256
```

The receipt must be canonical JSON with a SHA-256 envelope.

For probabilistic predictions:

```text
0.0 <= prediction_value <= 1.0
```

The receipt proves what model produced what forecast from what exact pre-decision evidence. It does not prove the model is economically good.

## Model identity and training provenance

A model candidate needs immutable identity over at least:

```text
model_family
model/config hyperparameters
feature schema version
training corpus SHA-256
training logical-operation membership
training time bounds
label definition
preprocessing manifest
seed / deterministic settings where applicable
code/version provenance
```

`model_id` should be content-derived rather than a mutable human label.

A later v0.16 implementation may define `pmo_<sha256>` identifiers for predictive model objects.

## Evaluation

Evaluation remains strictly chronological.

Minimum report dimensions:

### Statistical

- Brier score / calibration error for probability output
- MAE/RMSE for future net edge where applicable
- survival diagnostics for opportunity lifetime where applicable

### Economic

- realized paper PnL
- PnL per logical operation
- hit rate among predicted-positive opportunities
- drawdown proxy
- turnover / action count
- fee/slippage burden
- tail-loss diagnostics

### Causal / operational

- outcome by regime
- outcome by semantic route
- outcome by liquidity/freshness bucket
- model-versus-deterministic-policy disagreement matrix
- prediction stability across walk-forward folds

A model with better statistical metrics but worse untouched paper PnL must not be described as the better trading model.

## Decision integration

v0.16 is deliberately monotonic.

The initial predictive integration may only **downgrade or rank** existing paper candidates:

```text
base verifier verdict
→ regime gate
→ final deterministic paper verdict
→ predictive advisory score
→ predictive ranking / optional downgrade
```

Invariant:

```text
predictive_final_verdict <= deterministic_final_verdict
```

A model cannot manufacture positive edge, bypass `UNKNOWN`, override insufficient capacity/freshness/latency constraints, or grant itself execution authority.

Promotion of a predictive model into an active paper policy must reuse the existing evidence-bound promotion, lineage, revocation, and authority layers rather than inventing a parallel governance path.

## PnL objective

The role-model inspiration for v0.16 is production quant research where the terminal KPI is strategy PnL rather than isolated model accuracy.

For this repository the safe equivalent is **realized paper PnL**.

A candidate should therefore be evaluated on:

```text
sum(realized simulated proceeds - simulated starting capital - modeled costs)
```

with explicit route/operation accounting and no live funds.

## Wallet / trader behavior extension

Wallet and trader observations are a future feature source, not an execution mechanism.

A future event graph may model:

```text
wallet/entity
→ action
→ asset/venue/protocol
→ position/state transition
→ later outcome
→ inferred PnL / success label
```

These observations can become exogenous features only when provenance, event time, availability time, chain reorg/finality semantics, and label uncertainty are explicit.

No wallet private keys, signing, transaction submission, or copy-trading path belongs in v0.16.

## Relationship to RL

Reinforcement learning is intentionally deferred.

The prerequisite sequence is:

```text
v0.16 deterministic feature/label contract
→ supervised predictive baselines
→ chronological and walk-forward validation
→ stable paper-PnL evidence
→ v0.17 offline strategy learning / RL research
```

An RL environment should later expose explicit state/action/reward semantics such as:

```text
state  = market + route + regime + reliability + predictive state
action = SKIP | OBSERVE | EXECUTE_SIM(size_bucket)
reward = realized paper PnL - execution costs - risk/drawdown penalty
```

Offline RL must inherit the same anti-lookahead and logical-operation grouping guarantees as replay/holdout.

## Safety boundary

v0.16 remains paper-only.

It introduces no:

- exchange credentials;
- private account endpoints;
- order placement;
- signing keys;
- wallet control;
- transfers or bridges;
- live capital allocation;
- autonomous live execution.

The predictive layer learns from captured/replayable evidence and produces evidence-bound advisory forecasts only.

## Definition of done for the first implementation slice

- canonical `OpportunityFeatureVector` schema;
- deterministic feature builder from replay/observation evidence;
- event-time and outcome-availability leakage firewall;
- canonical feature-vector SHA-256;
- `PredictiveOpportunityReceipt` envelope and verifier;
- baseline scorer interface independent of ML framework;
- chronological evaluation fixture with realised paper-PnL reporting;
- tamper/leakage/retry-boundary regression tests;
- no change to the live/paper execution safety boundary.
