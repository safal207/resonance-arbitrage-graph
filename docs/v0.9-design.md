# v0.9 — Evidence-Bound Regime Execution Gate

## Goal

Make market regime causally active without creating a live-trading path.

```text
captured/public quotes
-> base route verifier
-> evidence-derived rolling market regime
-> explicit regime execution action
-> monotonic final paper verdict
-> evidence
-> observation/replay/holdout
```

The regime layer may only preserve or reduce permission. It cannot manufacture an executable opportunity that the base verifier rejected or merely observed.

## Verdict order

```text
REJECT < OBSERVE < EXECUTE_SIM
```

Invariant:

```text
final_verdict <= base_verdict
```

Default gate policy:

```text
NORMAL          -> ALLOW
VOLATILE        -> OBSERVE_ONLY
THIN_LIQUIDITY  -> OBSERVE_ONLY
DISLOCATED      -> OBSERVE_ONLY
UNKNOWN         -> REJECT
```

`UNKNOWN` is structurally forced to `REJECT` in `RegimeExecutionPolicy`; callers cannot configure missing/insufficient market-state evidence to allow execution.

## Evidence contract

Rolling market evidence now uses top-level evidence schema `resonance.arbitrage.evidence/v0.2` and binds:

- base verifier verdict;
- evidence-derived market regime;
- regime action;
- final post-gate verdict;
- full canonical `RegimeExecutionPolicy`;
- gate-policy SHA-256;
- rolling-window evidence and route/quote provenance.

The public `expected.verdict` is the final post-gate verdict. `expected.base_verdict` preserves the verifier-only conclusion. Observation memory validates the gate against the bound policy before accepting the evidence.

## Replay contract

Replay case, bundle and report schemas move to v0.2 because the regime execution policy is now part of the decision state.

Replay recomputes:

```text
quotes
-> route edges
-> base evaluate_route verdict
-> rolling regime
-> apply_regime_gate
-> final expected verdict
-> paper outcome class
```

Stored final labels are not trusted. `RegimeExecutionPolicy` is included in `ReplayCase.decision_fingerprint`, so changing `VOLATILE -> OBSERVE_ONLY` to `VOLATILE -> ALLOW` across retries under one `logical_operation_id` is decision drift and fails closed.

Replay v0.1 artifacts are intentionally not silently reinterpreted as v0.2 because they do not bind the new causal policy.

## Truth metrics

Outcome classification uses the final verdict. Therefore a route with:

```text
base = EXECUTE_SIM
regime = VOLATILE
action = OBSERVE_ONLY
final = OBSERVE
```

is `INDETERMINATE`, not TP/FP, even if a later paper edge is available. It does not enter the Opportunity Truth Rate denominator because the final system decision did not claim executability.

`UNKNOWN -> REJECT` is classified as `REJECTED`.

## Holdout

The v0.8 holdout frozen context now also includes canonical `RegimeExecutionPolicy`. Historical cases with different gate semantics cannot be mixed into one policy calibration corpus.

This makes volatility thresholds causally active for future calibration: changing a volatility threshold can change the derived regime, which can change the gate action, which can change the final `EXECUTE_SIM` population.

## Safety boundary

v0.9 remains paper-only. It adds no private exchange API, account access, signing, order placement/cancel, wallet interaction, transfer/bridge path, daemon or live execution.
