# v0.7 — Market-State Replay & Calibration Benchmark

v0.7 turns evidence-bound market state into an offline calibration laboratory. It replays captured quote snapshots and rolling windows, recomputes the route decision and regime, attaches a later paper outcome, and measures where the model is reliable or systematically wrong.

## Causal loop

```text
captured public quote state
  -> canonical replay case
  -> SHA-256 replay bundle
  -> rebuild route edges from snapshot + side + cost assumptions
  -> recompute verifier verdict
  -> recompute rolling-window market regime
  -> compare with later paper outcome
  -> TP / FP / EXPIRED / REJECTED / INDETERMINATE
  -> metrics by regime and semantic route
  -> advisory threshold sensitivity
```

Stored verdict or regime labels are deliberately absent from the replay input. The benchmark derives both again from the captured market state and policy values.

## Replay case

A `ReplayCase` binds:

- `case_id` and `logical_operation_id`;
- retry `attempt`;
- detection/evaluation timestamps;
- starting paper capital;
- exact normalized `QuoteSnapshot` rows;
- exact evidence-bound `RollingMarketWindow` objects;
- route legs as `(snapshot_index, BUY|SELL, CostAssumption)` descriptors;
- verifier `Policy`;
- `RegimePolicy`;
- a later paper-only outcome.

The route is rebuilt from quote snapshots with `quote_to_trade_edges(...)`; serialized edge rates or stored verdicts are never trusted.

## Lookahead boundary

Replay decision input cannot contain market data from after `evaluation_time_ms`.

The case rejects:

```text
snapshot.observed_at_ms > evaluation_time_ms
snapshot.freshness_reference_ms > evaluation_time_ms
rolling sample observed_at_ms > evaluation_time_ms
rolling sample freshness_reference_ms > evaluation_time_ms
```

The later paper outcome may occur after evaluation because it is a label used only after the decision is recomputed.

## Retry identity

Multiple attempts under one `logical_operation_id` are allowed only while prior attempts are indeterminate.

For one logical operation:

- attempts must be contiguous starting at 1;
- `detected_at_ms` must remain stable;
- the complete decision fingerprint must remain stable;
- a terminal outcome cannot be followed by another attempt.

Metrics collapse retries to the highest valid attempt so retries cannot improve or degrade benchmark rates by duplication.

## Fail-closed regime evidence

The replay runner calls the v0.6 rolling-window regime derivation again. If rolling evidence is incomplete and the route would otherwise be executable/observable, the benchmark outcome becomes `INDETERMINATE`, not a fabricated true positive.

Tampered window tails, missing route windows, malformed timestamps, discontinuous routes or invalid bundle digests fail before metrics are produced.

## Calibration report

`benchmark_bundle(...)` produces:

- all collapsed replay results;
- overall metrics;
- metrics grouped by exact derived regime;
- metrics grouped by semantic route ID;
- canonical report payload + SHA-256.

Metrics use the same definitions as opportunity memory:

```text
Opportunity Truth Rate = TP / (TP + FP)
False Opportunity Rate = FP / (TP + FP)
Route Survival Rate = (TP + FP) / (TP + FP + EXPIRED)
Prediction Error = observed_edge_bps - expected_edge_bps
```

## Threshold sensitivity

`threshold_sensitivity(...)` replays the same immutable bundle across a grid of:

```text
execute_net_edge_bps
volatile_return_bps
```

The output reports the resulting truth metrics, `EXECUTE_SIM` population and regime distribution for every grid point.

This output is **advisory only**. It never mutates `Policy`, `RegimePolicy`, ranking configuration or live scanner behavior.

## Bundle integrity

A replay bundle is serialized as:

```json
{
  "payload": {"schema": "resonance.arbitrage.replay-bundle/v0.1", "cases": []},
  "sha256": "..."
}
```

Loading verifies the digest over the raw payload, reconstructs strongly typed cases, requires canonical round-trip equality and verifies the reconstructed digest again.

Changing a quote, timestamp, rolling sample, route leg, policy, outcome or case identity therefore changes the bundle digest.

## CLI

```bash
resonance-replay-benchmark replay-bundle.json
```

Optional advisory grid:

```bash
resonance-replay-benchmark replay-bundle.json \
  --execute-threshold-bps 20,30,40,50 \
  --volatile-threshold-bps 50,75,100
```

The CLI reads local JSON only. It performs no network requests.

## Safety boundary

v0.7 is offline and paper-only. It adds no private exchange API, account access, signing, order placement/cancel, wallet interaction, transfer, bridge, daemon or live-execution path.
