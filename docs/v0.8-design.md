# v0.8 — Holdout Policy Calibration

## Goal

v0.8 prevents the execute threshold from being selected and graded on the same replay history.

```text
captured replay corpus
  -> logical-operation groups
  -> strict chronological split
  -> calibration bundle
  -> execute-threshold grid
  -> calibration-only selection
  -> freeze selected candidate
  -> untouched validation bundle
  -> out-of-sample gate
  -> deterministic holdout report
```

The feature remains offline and paper-only. It does not modify the live scanner, place orders, hold keys, sign requests, or move funds.

## Why v0.8 tunes only execute threshold

v0.7 can replay sensitivity for both `execute_net_edge` and `volatile_return_bps`, but those parameters have different causal roles today.

`execute_net_edge` directly changes the verifier decision boundary between `EXECUTE_SIM` and `OBSERVE`.

`volatile_return_bps` currently changes the derived `NORMAL` / `VOLATILE` regime label, but the runtime verifier does not suppress execution merely because the regime is `VOLATILE`. Optimizing that label threshold against overall Opportunity Truth Rate would therefore be fake calibration: it would not causally change the predicted execution population.

v0.8 deliberately tunes only the causally active execute threshold. The complete `RegimePolicy` is frozen as measurement context. A future regime-gated execution policy can make regime thresholds valid holdout candidates once they causally affect the decision.

## Split contract

Splitting happens at `logical_operation_id`, never at raw attempt rows. All retries for one logical operation remain on one side of the split. Chronological mode requires:

```text
max(calibration.detected_at_ms) < min(validation.detected_at_ms)
```

If no strict time boundary can satisfy the explicit minimum operation counts, the report fails closed as `INSUFFICIENT_CORPUS`.

The requested validation fraction is a target, not permission to violate minimum counts or strict temporal ordering. The closest valid boundary is selected deterministically.

## Frozen measurement context

Only `Policy.execute_net_edge` is removed from the corpus context fingerprint. The following remain frozen and must be uniform across the corpus:

- all other `Policy` fields, including `observe_net_edge`;
- the full `RegimePolicy`;
- the rolling-window policy used to derive short-window volatility.

This prevents one threshold from being calibrated across incompatible freshness, latency, regime or rolling-window semantics.

## Candidate selection

Each execute-threshold candidate is replayed only against the calibration bundle. For every candidate the report records:

- replay metrics;
- `EXECUTE_SIM` population;
- TP + FP truth-event count;
- TP + FP + EXPIRED survival-event count;
- Wilson lower bound for Opportunity Truth Rate;
- Wilson lower bound for Route Survival Rate;
- negative-only overprediction penalty;
- deterministic result digest;
- eligibility reasons.

Explicit `HoldoutPolicy` guardrails control minimum sample support and lower-bound floors. There are no hidden trading-quality defaults in the CLI; the caller supplies the guardrails.

Among eligible calibration candidates, the deterministic selection order is:

```text
higher truth-rate lower bound
higher survival-rate lower bound
more truth events
more EXECUTE_SIM observations
lower overprediction penalty
lower execute threshold only as final deterministic tie-break
```

The final threshold tie-break exists only to make equal evidence deterministic. It is not an economic claim that lower thresholds are superior.

## Validation firewall

After calibration chooses one candidate, that candidate is frozen. Only that candidate is evaluated on validation.

Validation is allowed to produce only one of these effects:

```text
PASSED_HOLDOUT
INSUFFICIENT_VALIDATION
VALIDATION_FAILED
```

Validation must never choose a fallback candidate, reorder the grid, or influence the calibration winner. If the calibration winner fails out of sample, the correct result is `VALIDATION_FAILED`, not “try the runner-up until one passes.”

This is the central anti-overfitting invariant in v0.8.

## Uncertainty-sensitive guardrails

Raw ratios can make tiny samples look deceptively perfect, so v0.8 uses the Wilson score lower bound.

For a proportion `p = successes / total`, the report compares the lower confidence bound rather than only the point estimate. `confidence_z` is explicit in `HoldoutPolicy` and is evidence-bearing configuration.

A one-for-one perfect sample therefore carries less evidence than ten-for-ten under the same confidence setting.

## Status model

```text
INSUFFICIENT_CORPUS
INSUFFICIENT_CALIBRATION
NO_ELIGIBLE_CALIBRATION_POLICY
INSUFFICIENT_VALIDATION
VALIDATION_FAILED
PASSED_HOLDOUT
```

`PASSED_HOLDOUT` means only that the selected paper-policy candidate passed the caller-supplied offline holdout guardrails. It is not a live-trading instruction or a profitability guarantee.

## Evidence

The canonical holdout report binds:

- source replay-bundle SHA-256;
- frozen measurement-context SHA-256;
- holdout policy;
- complete execute-threshold grid;
- calibration/validation subset bundle SHA-256 values;
- exact logical-operation membership of both splits;
- strict chronological boundary timestamps;
- every calibration candidate evaluation;
- selected candidate;
- validation evaluation of that candidate only;
- final status and reasons;
- fixed selection-rule identifier;
- `validation_not_used_for_selection = true`;
- `advisory_only = true`.

The report is canonical JSON with SHA-256 envelope verification. Fixed firewall/advisory fields are validated in addition to the digest.

## CLI

```bash
resonance-holdout-calibration replay-bundle.json \
  --validation-fraction 0.30 \
  --execute-threshold-bps 20,30,40,50 \
  --min-calibration-operations 20 \
  --min-validation-operations 10 \
  --min-calibration-truth-events 10 \
  --min-validation-truth-events 5 \
  --min-truth-lower-bound 0.60 \
  --min-survival-lower-bound 0.70 \
  --confidence-z 1.96
```

These numbers are examples, not recommended market settings. The CLI reads a local replay-bundle envelope and writes the holdout report to stdout. It has no network path.

## Tests

Regression coverage includes:

- retries remain on one side of the split;
- validation is strictly later than calibration;
- validation outcome mutation cannot change the selected candidate;
- validation failure does not trigger fallback candidate search;
- insufficient validation support fails closed;
- insufficient corpus and missing strict timestamp boundary fail closed;
- heterogeneous untuned engine policy is rejected;
- `RegimePolicy` is frozen context, not a fake tuning dimension;
- execute candidates cannot cross below the corpus observe threshold;
- report tampering and firewall-flag forgery are detected;
- Wilson bounds penalize tiny samples.
