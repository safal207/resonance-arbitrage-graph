# v0.6 — Evidence-Bound Rolling Market State

v0.6 removes the last caller-supplied regime feature from the live paper path. Short-window volatility is derived from a deterministic rolling window of public quote snapshots and the exact window is bound into evidence.

## Causal loop

```text
public GET-only quote samples
  -> strict timestamp-ordered rolling window
  -> canonical window JSON + SHA-256
  -> window summary
  -> sample-to-sample mid-price returns
  -> short-window return volatility
  -> route-specific regime features
  -> deterministic regime
  -> quote + rolling-window-bound evidence
  -> observation memory
  -> exact-regime reliability
```

## Rolling window identity

A `RollingMarketWindow` contains samples for exactly one:

```text
venue + symbol + base_asset + quote_asset
```

Each sample preserves:

- bid/ask price and quantity;
- local observation time;
- timestamp class and optional exchange-published timestamp;
- freshness reference;
- source URL and metadata URL.

Input ordering is authoritative. Reordered or duplicate timestamps are rejected rather than silently sorted.

## Window policy

`RollingWindowPolicy` is explicit evidence-bearing policy:

```text
horizon_ms
min_samples
min_coverage_ratio
```

A summary is incomplete when sample count, time coverage or return observations are insufficient. Incomplete rolling evidence produces `UNKNOWN`; it never guesses `NORMAL`.

## Volatility

For each consecutive sample pair:

```text
return_bps = (current_mid / previous_mid - 1) * 10_000
```

Short-window volatility is the population standard deviation of those sample-to-sample returns. It is not annualized and is therefore tied to the sampling cadence/window policy recorded in evidence.

For a multi-leg route, v0.6 conservatively uses the maximum volatility among the exact markets bound to that route.

## Tail binding

The latest sample of each rolling market window must equal the exact public `QuoteSnapshot` that backs the current route edge(s).

This prevents a causal mismatch such as:

```text
old rolling window -> volatility proof
new unrelated quote -> opportunity decision
```

The accepted chain is:

```text
rolling samples ... -> final sample == current route snapshot -> route edge
```

## Evidence

`make_window_regime_evidence_receipt(...)` binds:

- normal v0.2 edge↔snapshot provenance;
- regime features, reasons and `RegimePolicy`;
- full canonical rolling-window samples for every route-bound market;
- per-window SHA-256;
- per-window summary/time bounds/sample count;
- explicit feature binding: `short_window_return_volatility_bps = derived_from_rolling_window`;
- exact tail-binding semantics.

Tampering with price, timestamp, source provenance, window policy or ordering changes the window digest and therefore the final evidence digest.

## Live paper scan

`resonance-live-scan` now samples public data synchronously before evaluating routes. Defaults:

```text
rolling_samples = 5
rolling_interval_ms = 1000
rolling_horizon_ms = 5000
rolling_min_coverage_ratio = 0.8
```

The scanner no longer accepts `--short-window-volatility-bps`.

These defaults are paper-model defaults, not claims that a five-second window is universally optimal. They are exposed as CLI parameters and recorded in output/evidence so calibration can evolve without hiding assumptions.

## Safety boundary

v0.6 remains paper-only and synchronous. It introduces no daemon, background trading loop, private API, account access, signing, order placement/cancel, wallet interaction, transfer, bridge or live execution path.
