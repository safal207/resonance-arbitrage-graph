# v0.13 — Evidence-Bound Policy Promotion Gate

v0.13 adds a governance boundary between offline calibration/stability evidence and a policy becoming a canonical promotable **paper** policy.

```text
verified replay bundle
  -> verified v0.11 walk-forward report
  -> verified v0.12 stability decomposition
  -> calibration-selected policy support across folds
  -> latest calibration-selection check
  -> promotion guardrails
  -> deterministic promotion decision
  -> SHA-256 promotion receipt
```

Promotion is not live execution. The layer performs no exchange authentication, order placement, signing, transfers, wallet actions or deployment.

## Candidate-selection firewall

The promotion candidate is selected only from candidates already chosen by calibration inside walk-forward folds. For each exact pair:

```text
(execute_net_edge_bps, volatile_return_bps)
```

v0.13 counts calibration selections across folds. A unique highest-support pair is the historical calibration-consensus candidate.

Validation never chooses between candidates. It may only veto that already-determined candidate. If candidate A wins calibration consensus but fails its validation-veto floor, candidate B is not promoted as a fallback.

### Latest-calibration freshness firewall

Walk-forward calibration sets expand over time, so a historical majority can become stale. Therefore a second calibration-only rule applies:

```text
historical consensus candidate
MUST equal
candidate selected by the latest calibration fold
```

If the latest calibration fold selected a different policy, promotion fails closed with `LATEST_CALIBRATION_DISAGREES`. The latest candidate is not automatically promoted either: the system requires both historical support and current calibration agreement.

This check uses only calibration selections. No validation or post-hoc decomposition data can choose or replace the candidate.

## Promotion guardrails

`PolicyPromotionGuardrails` exposes explicit evidence requirements:

```text
min_selected_policy_folds
min_candidate_supporting_folds
min_consensus_fraction
min_candidate_validation_pass_rate
```

Promotion additionally requires `WalkForwardStatus.PASSED_STABILITY`, `DecompositionStatus.STABLE_BASELINE`, a unique consensus candidate and agreement with the latest calibration selection.

## Explicit statuses

```text
PROMOTED
BLOCKED_WALK_FORWARD
BLOCKED_DECOMPOSITION
INSUFFICIENT_SELECTED_POLICIES
AMBIGUOUS_CALIBRATION_CONSENSUS
CONSENSUS_BELOW_FLOOR
INSUFFICIENT_CANDIDATE_SUPPORT
LATEST_CALIBRATION_DISAGREES
CANDIDATE_VALIDATION_BELOW_FLOOR
```

Ambiguity, insufficient evidence and stale consensus all fail closed.

## Evidence

Schema:

```text
resonance.arbitrage.policy-promotion-report/v0.1
```

The canonical payload binds:

- replay bundle SHA-256;
- walk-forward report SHA-256;
- stability-decomposition report SHA-256;
- frozen joint policy-context SHA-256;
- promotion guardrails;
- every calibration-selected candidate and exact supporting fold indexes;
- which supporting folds later passed or failed validation;
- the final promotion decision and candidate, if any;
- calibration-only candidate-selection semantics;
- validation-veto-only semantics;
- the latest-calibration-must-match-consensus invariant;
- decomposition-never-selects-policy semantics;
- explicit paper-only semantics.

The envelope verifier recomputes candidate support semantics and the promotion decision before accepting the SHA-256. The full bundle-binding verifier then reruns the evidence chain and requires canonical reproduction from the source bundle, walk-forward report and decomposition report.

## Decomposition semantics

v0.12 remains post-hoc diagnostic evidence. It may block promotion when the upstream evidence is not a stable baseline, but its diagnostic drivers never select, mutate or rescue a policy.

## CLI

`resonance-policy-promotion` rebuilds walk-forward stability and stability decomposition from a local replay bundle, applies promotion guardrails and emits the deterministic promotion envelope.

All thresholds are explicit caller-supplied governance/diagnostic parameters, not universal market constants or return claims.

## Safety boundary

v0.13 remains offline/paper-only and adds no private exchange API access, account credentials, order placement, signing, wallet interaction, transfers, bridges, deployment daemon or autonomous live execution.
