# v0.16.3 — One-Shot Corpus Runner & Research Readiness Gate

## Purpose

v0.16.2 established an append-only public-market replay corpus. v0.16.3 makes one honest temporal collection cycle operational without changing the evidence model:

```text
public decision quotes + rolling window
    -> append DECISION
    -> persist corpus
    -> wait configured horizon
    -> fresh public outcome quotes
    -> recompute exact semantic route
    -> append OUTCOME
    -> reload/verify corpus
    -> export canonical ReplayBundle
    -> research-readiness gate
    -> optional HistoricalMean vs CatBoost walk-forward
```

The runner is an orchestration layer. It does not create a second replay schema and it does not grant a predictive model execution authority.

## Crash / retry semantics

The decision record is persisted **before** the horizon wait. If the process exits after capture, the operation remains pending in the v0.16.2 corpus. A later operator may resolve it with the existing `resonance-real-market-corpus resolve` command.

A new one-shot run resolves only the operation IDs that it captured itself. Pre-existing pending operations are never silently closed by fresh quotes from a later run.

## Horizon invariant

For a decision at `t_decision` and configured horizon `H`:

```text
outcome_not_before = t_decision + H
```

The runner refuses to append an outcome unless:

1. the injected/real clock has reached `outcome_not_before`, and
2. every stored public outcome snapshot has `observed_at_ms >= outcome_not_before`.

If either check fails, the decision remains pending. The runner does not shorten the horizon to make a sample terminal.

## Atomic outcome batch

All newly captured decision cases are resolved in memory first. Outcome records are appended and persisted only after every selected route can be reconstructed from the fresh public market round. This avoids half-resolving a one-shot batch because one market was missing.

## Run receipt

Each completed run emits a content-addressed receipt binding:

- venue and explicit pair list;
- configured horizon;
- decision and outcome timestamps;
- corpus SHA before capture;
- corpus SHA after decision persistence;
- corpus SHA after terminal outcomes;
- captured and resolved logical-operation IDs;
- exported ReplayBundle SHA;
- research-report SHA.

The receipt remains `paper_only=true` and `public_market_data_only=true`.

## Research-readiness gate

Model complexity is not evidence. The runner therefore separates **corpus readiness** from **model performance**.

Default gate:

```text
minimum terminal operations = 100
minimum training rows       = 20
required terminals          = max(100, 20 + 1) = 100
```

The `+1` guarantees at least one chronological validation row beyond the configured training minimum.

Statuses:

- `NOT_READY` — terminal corpus is below the required threshold; CatBoost is not invoked.
- `READY` — corpus is large enough, but benchmark execution was not requested.
- `BENCHMARK_COMPLETE` — the existing leakage-safe CatBoost walk-forward comparison ran and its payload SHA is bound into the report.
- `BENCHMARK_UNAVAILABLE` — benchmark was requested but the optional ML dependency is unavailable; collection remains valid.
- `BENCHMARK_NOT_EVALUABLE` — corpus passed the coarse count gate but the existing chronological evaluator found no valid folds (for example due to target-availability timing).

No status promotes a model or paper policy automatically.

## Benchmark evidence

When benchmark execution is enabled, v0.16.3 calls the existing v0.16 CatBoost walk-forward engine over the exported canonical `ReplayBundle`. The comparison payload and SHA must match exactly before they may be embedded in the research report.

This keeps a single causal path:

```text
real public corpus
    -> canonical ReplayBundle
    -> leakage-safe PredictiveDataset
    -> HistoricalMean baseline
    -> CatBoost candidate
    -> walk-forward comparison
    -> research evidence
```

No additional ETL layer is introduced between corpus evidence and model evaluation.

## CLI

```bash
resonance-corpus-runner \
  --corpus data/corpus.json \
  --replay-output data/replay.json \
  --receipt-output data/last-run.json \
  --venue binance \
  --pair BTCUSDT:BTC:USDT \
  --pair ETHBTC:ETH:BTC \
  --pair ETHUSDT:ETH:USDT \
  --start-asset USDT \
  --amount 1000 \
  --fee-bps 10 \
  --slippage-bps 5 \
  --horizon-ms 60000
```

To request the existing CatBoost benchmark once the corpus is large enough:

```bash
resonance-corpus-runner ... --benchmark-when-ready
```

That option requires the optional `ml-catboost` extra only when the readiness threshold is reached. Missing ML dependencies do not invalidate already collected corpus evidence.

## Trust boundary

This remains a public-data, paper-only research system.

It does **not**:

- use exchange credentials or private account APIs;
- sign wallet messages or transactions;
- place orders;
- move funds;
- claim future top-of-book paper edge equals executable fill PnL;
- activate or promote a learned policy automatically.

The next scientific milestone is not another model. It is a sufficiently large, temporally honest public corpus and a stable out-of-sample comparison whose result survives new observations.
