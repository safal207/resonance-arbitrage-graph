# v0.16.4 — Corpus Quality Gate

## Why this layer exists

v0.16.3 introduced a quantity threshold before the paper-only CatBoost benchmark can run. Quantity alone is not enough.

A single public-market scan can produce several closely related routes. Repeating that pattern can create 100 terminal logical operations while representing only a handful of distinct market moments. Treating those rows as 100 independent observations would overstate the amount of evidence and make research readiness easy to game accidentally.

v0.16.4 therefore separates two questions:

1. **Do we have enough terminal operations?**
2. **Are those operations distributed across enough independent market evidence?**

The CatBoost benchmark may run only when both answers are yes.

## Canonical quality evidence

`CorpusQualityReport` is deterministic and content-addressed. It binds:

- the exact real-market corpus SHA-256;
- the exact quality-policy SHA-256;
- terminal logical-operation count;
- counts per decision batch (`evaluation_time_ms`);
- effective decision-batch count;
- largest decision-batch share;
- temporal span between the earliest and latest terminal decision batches;
- counts per semantic route topology;
- effective route count;
- largest route share;
- distinct route-market identities actually used by terminal routes;
- regime counts recomputed from the existing decision-time replay evidence;
- the exact failed quality dimensions;
- final `quality_ready` state.

The quality report is embedded into and SHA-bound by `CorpusResearchReport`, which is already bound by the one-shot runner receipt.

## Effective counts

Distinct counts alone still allow concentration. For example, 100 operations can technically cover 20 timestamps while 81 of them come from one timestamp.

For decision batches and route topologies, v0.16.4 therefore also computes an inverse-concentration effective count:

```text
effective_count = 1 / sum(p_i^2)
```

where `p_i` is the fraction of terminal operations in group `i`.

Examples:

- 10 equally weighted batches -> effective count = 10;
- 2 equally weighted batches -> effective count = 2;
- one overwhelmingly dominant batch -> effective count approaches 1 even if many tiny batches exist.

This is a diversity/evidence diagnostic, not a statistical-independence proof.

## Route topology identity

Quality diversity intentionally does **not** use fee/slippage assumptions as part of route identity. Otherwise changing cost configuration could manufacture apparently distinct routes without changing the actual market path.

A route topology is hashed from ordered legs containing only:

- venue;
- symbol;
- base asset;
- quote asset;
- BUY/SELL side.

## Default research gates

The default `CorpusQualityPolicy` requires:

| Dimension | Default |
|---|---:|
| distinct decision batches | >= 20 |
| effective decision batches | >= 10.0 |
| temporal span | >= 3,600,000 ms (1 hour) |
| distinct route topologies | >= 3 |
| effective routes | >= 2.0 |
| distinct route markets | >= 3 |
| distinct regimes | >= 2 |

These are in addition to the existing default minimum of 100 terminal operations and the minimum rows needed for walk-forward training.

All thresholds are explicit CLI/configuration inputs and therefore appear in a content-addressed quality-policy SHA. Lowering them is visible evidence, not a hidden implementation detail.

## Readiness semantics

```text
quantity_ready = terminal_operations >= required_terminal_operations
quality_ready  = every CorpusQualityPolicy dimension passes

RESEARCH_READY = quantity_ready AND quality_ready
```

If either gate fails:

- `CorpusResearchReport.status = NOT_READY`;
- failed quality dimensions are included in the embedded quality report;
- CatBoost is not called;
- no comparison payload is produced.

Passing both gates only means the corpus is eligible for research evaluation. It does **not** mean:

- CatBoost is better than the historical baseline;
- the paper edge is executable fill PnL;
- a strategy is profitable;
- a model or policy should be promoted;
- live trading is authorized.

## Regime diversity

Regime labels are not caller-supplied metadata. They are recomputed with the existing `replay_case()` logic from the decision-time quotes, rolling windows and bound regime policy for each terminal logical operation.

This keeps the quality layer downstream of the same anti-lookahead evidence contract used by replay and predictive evaluation.

## Safety boundary

This layer remains:

- public-market-data only;
- paper evaluation only;
- credential-free;
- order-free;
- wallet/signature-free;
- transfer-free;
- live-capital-free;
- automatic-promotion-free.

## Next research milestone

After this gate is proven on CI, the useful next step is not another model. It is repeated real collection until the corpus passes quantity **and** quality, followed by the already-existing untouched chronological `HistoricalMean vs CatBoost` walk-forward comparison.
