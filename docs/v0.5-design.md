# v0.5 — Regime-Aware Calibration

v0.5 makes market regime a first-class, evidence-bound reliability segment.

## Causal loop

```text
public quote snapshots
  -> exact route/snapshot bindings
  -> route-specific feature vector
  -> deterministic regime classification
  -> regime-bound evidence
  -> opportunity observation
  -> exact-regime reliability profile
  -> reliability-adjusted paper ranking
```

The regime layer does not replace the verifier and does not create an execution path.

## Regimes

- `NORMAL`
- `VOLATILE`
- `THIN_LIQUIDITY`
- `DISLOCATED`
- `UNKNOWN`

`UNKNOWN` is fail-closed and cannot be reliability-ranked.

## Route-bound features

The classifier consumes `RegimeFeatures`:

```text
normalized_spread_bps
route top-of-book capacity ratio
quote_age_ms
quote_age_dispersion_ms
cross_rate_dislocation_bps
short_window_return_volatility_bps (optional)
```

### Spread

Spread is derived from the public quote snapshots that are actually bound to the candidate route. Unrelated market pairs do not affect the candidate regime.

### Capacity

Raw quantities from different assets are never compared directly. For every route leg:

```text
capacity_ratio = edge_capacity_in_src_asset / current_amount_in_same_src_asset
```

The regime feature is the minimum leg ratio. This is a screening feature; the causal verifier remains authoritative for actual capacity rejection.

### Freshness

Freshness uses the same snapshot freshness reference already used by market evidence. Future timestamps fail closed. Stale or materially time-incoherent route snapshots produce `UNKNOWN`.

### Cross-rate dislocation

For a closed route, dislocation is derived from raw quote rates:

```text
abs(product(raw_edge_rates) - 1) * 10_000
```

It is not accepted as a caller-supplied label.

### Short-window volatility

Short-window return volatility is optional because the current public snapshot adapter does not maintain a time-series window. When supplied, it is explicit input and is marked `caller_supplied_explicit_feature` in evidence. A future version can replace this with an evidence-bound rolling window.

## Classification precedence

Overlapping conditions use deterministic precedence:

```text
freshness failure -> UNKNOWN
DISLOCATED
THIN_LIQUIDITY
VOLATILE
NORMAL
```

A severe route dislocation therefore cannot be hidden by an ordinary volatility label, and thin executable depth outranks tape volatility.

Default thresholds are explicit `RegimePolicy` fields and are bound into evidence.

## Evidence binding

`make_regime_market_evidence_receipt(...)`:

1. Reuses the v0.2 exact edge-to-snapshot provenance binding.
2. Recomputes route-specific regime features.
3. Re-runs classification under the supplied/default `RegimePolicy`.
4. Rejects feature or regime-label tampering.
5. Adds regime, features, feature provenance, reasons and policy to the SHA-256 receipt.

## Context binding

`merge_regime_context(...)` attaches:

```text
regime
regime_features
regime_reasons
```

to existing market context and rejects conflicting caller-supplied values.

## Reliability boundary

v0.4 already segments reliability by `route_id`, `venue` and `regime`. v0.5 makes the regime derived rather than merely caller-labeled.

History from `NORMAL` cannot affect a `VOLATILE`, `THIN_LIQUIDITY` or `DISLOCATED` candidate. `UNKNOWN` candidates are `INELIGIBLE` for reliability ranking.

No hierarchical fallback across regimes is implemented in v0.5.

## Live paper scan

`resonance-live-scan` now derives and emits `market_regime` for every surfaced cycle. Optional measured short-window volatility can be supplied with:

```bash
--short-window-volatility-bps 82
```

This input does not place orders and does not alter the paper-only safety boundary.

## Safety boundary

v0.5 remains paper-only. It adds no private exchange API, account access, signing, order placement/cancel, wallet interaction, transfer, bridge or live execution path.
